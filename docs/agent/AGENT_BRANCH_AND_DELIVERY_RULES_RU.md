# Правила веток и передачи изменений агентом

Этот документ дополняет корневой `AGENTS.md` и фиксирует рабочий процесс между агентом и владельцем проекта.

## Модель работы

1. Владелец проекта хранит канонический репозиторий и выполняет независимую проверку.
2. Агент готовит код, тесты, документацию и patch-архив.
3. Агент всегда указывает ветку, базовый checkpoint, рекомендуемый commit и команды проверки.
4. Владелец накладывает архив, запускает проверки и возвращает замечания.
5. Исправления до принятия checkpoint продолжаются в той же ветке.
6. После принятия ветка сливается в `main`, получает checkpoint/tag и удаляется.

## Когда создавать новую ветку

Новая ветка нужна для:

- нового этапа дорожной карты;
- отдельного вертикального среза;
- изменения, которое может быть принято или отклонено независимо;
- hotfix уже принятого и влитого checkpoint.

Новая ветка не нужна для:

- `fix1`, `fix2` и последующих замечаний к ещё не принятому патчу;
- дополнения тестов того же этапа;
- исправления документации того же checkpoint;
- корректировки packaging или runner того же этапа.

## Обязательный блок в каждой выдаче кода

Агент обязан публиковать готовые команды без placeholders:

```bash
git switch main
git pull --ff-only
git switch -c feature/n1-transport-boundary
```

После распаковки патча:

```bash
git status --short
git diff --check
git add AGENTS.md docs scripts tests RUN_NETWORK_CONTRACT_TESTS.ps1
git commit -m "feat(network): add N1 transport lifecycle boundary"
```

При замечаниях к этому же этапу новая ветка не создаётся:

```bash
git switch feature/n1-transport-boundary
git add <исправленные файлы>
git commit -m "fix(network): harden N1 transport lifecycle boundary"
```

Точный список `git add` агент формирует по фактическому составу каждого архива.

## Правило checkpoint

Checkpoint создаётся только после независимого подтверждения:

- focused profile PASS;
- полный релевантный regression PASS;
- runtime/process проверки PASS, если применимо;
- рабочее дерево чистое;
- содержимое merge tree соответствует проверенному патчу.
