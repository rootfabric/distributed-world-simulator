# Атмосферный слой v1

## Цель

Атмосфера не является частью terrain generator, biome pipeline или celestial coordinate system. Это отдельный слой пространства, привязанный к небесному телу через конфигурацию тела.

```text
CelestialSystem
    └── body: earth
          └── atmosphere_config
                └── PlanetAtmosphere
                      ├── Environment state provider
                      ├── CloudLayerPlugin
                      ├── AuroraPlugin (будущий)
                      ├── StormPlugin (будущий)
                      └── DustPlugin (будущий)
```

Такой порядок не позволяет атмосфере менять высоту поверхности, биомы, размещение растительности, физику Луны или абсолютные координаты.

## Контракты

### Celestial body

В `config/planets/celestial_system.json` тело может содержать:

```json
"atmosphere_config": "res://config/atmospheres/earth.json"
```

Отсутствие поля означает отсутствие атмосферы. Поэтому Луна продолжает работать без атмосферного кода.

### PlanetAtmosphere

`PlanetAtmosphere` описывает атмосферный объём:

- нижнюю и верхнюю границы;
- высоту полного эффекта;
- высоту начала затухания;
- параметры неба и тумана;
- список подключаемых эффектов.

Он получает абсолютную позицию наблюдателя, переводит её в body-local координаты и формирует неизменяемый контекст для плагинов.

### Atmosphere plugin

Каждый эффект наследует `atmosphere_plugin_base.gd` и реализует:

```gdscript
func setup(owner_reference, config_value: Dictionary, logger_reference = null) -> bool
func update_layer(context: Dictionary, delta: float) -> void
func set_layer_active(value: bool) -> void
func create_snapshot() -> Dictionary
```

Плагин не имеет права напрямую изменять terrain pipeline. Он может создавать только собственные дочерние визуальные или физические узлы.

## Выбор активной атмосферы

`AtmosphereManager` обновляет все зарегистрированные атмосферы и выбирает атмосферу с наибольшей интенсивностью. Только выбранная атмосфера управляет общим `WorldEnvironment` viewport.

Это важно для будущего сценария с несколькими планетами и станциями:

- геометрические плагины каждого тела остаются независимыми;
- в один момент viewport получает один согласованный sky/fog state;
- вне атмосфер восстанавливается исходное космическое окружение Луны;
- конфигурация атмосферы не влияет на механизм floating origin.

## Земная атмосфера

Текущий пример:

- нижняя граница: `-1 км`;
- верхняя граница: `100 км`;
- полный голубой эффект: до `18 км`;
- постепенное затемнение: до `65 км`;
- переход в космический фон: `65–100 км`;
- глубинный туман действует только до `24 км`.

Небо реализовано через отдельный `ProceduralSkyMaterial`. Цвет верхней части, горизонта, земли и ambient light интерполируется по высоте. На глобальном LOD вокруг Земли не создаётся яркая прозрачная сфера, поэтому атмосфера не выглядит как толстая оболочка при межпланетном наблюдении.

## Облачный плагин

`CloudLayerPlugin` подключён конфигурацией и не захардкожен в `PlanetAtmosphere`.

Параметры вынесены в `config/atmosphere_plugins/earth_low_clouds.json`:

- базовая высота: `4 км`;
- толщина: `850 м`;
- локальный радиус облачного патча: `70 км`;
- максимальная высота наблюдателя: `32 км`;
- покрытие, размеры, прозрачность и ветер;
- число кандидатов и максимальное количество экземпляров.

Облака создаются как один `MultiMeshInstance3D` с процедурно созданной alpha-текстурой. Патч хранится относительно локального anchor, а при движении наблюдателя меняется только позиция root. Это не отправляет координаты порядка радиуса Земли в каждый GPU-instance и не создаёт отдельный Node для каждого облака.

Облака полностью выключаются на глобальном LOD и при нахождении вне атмосферы.

## Добавление полярного сияния

Для нового явления достаточно:

1. создать `aurora_layer_plugin.gd`, наследующий базовый контракт;
2. создать отдельный JSON с высотой, широтой, цветом и интенсивностью;
3. добавить descriptor в массив `plugins` атмосферы Земли;
4. не изменять `AtmosphereManager`, `PlanetAtmosphere`, terrain и CelestialSystem.

Контекст уже передаёт:

- `body_id`;
- абсолютную и body-local позицию;
- высоту;
- направление от центра тела;
- радиус тела и высоту поверхности;
- интенсивность атмосферы;
- активную камеру.

Этого достаточно для сияний, гроз, пылевых бурь, слоёв аэрозолей, вулканического пепла и локальной погоды.

## LOD и производительность

```text
межпланетное расстояние / global LOD
    sky = космос
    cloud plugins = off
    atmosphere geometry = отсутствует

100–32 км
    sky постепенно темнеет
    clouds = off
    fog = off

32–24 км
    sky active
    clouds fade
    fog = off

ниже 24 км
    sky active
    fog active
    clouds active
```

Стоимость кадра атмосферы почти постоянна: один расчёт высоты и обновление нескольких параметров Environment. Облака перестраиваются только после смещения anchor на `14 км`, а не каждый кадр.

## Будущее серверное разделение

Atmosphere является body-owned component. При переходе к нескольким space servers:

```text
space/earth authority
    ├── Earth terrain
    ├── Earth atmosphere state
    └── local atmospheric phenomena

space/moon authority
    ├── Moon terrain
    └── no atmosphere
```

Клиент получает descriptor атмосферы вместе с body snapshot. Долгоживущие явления могут иметь собственные entity IDs и реплицироваться отдельно, а визуальные локальные облака могут оставаться client-generated по seed и погодному snapshot.
