# v15.4 — фундамент предметов, контейнеров и сборок

## Реализованный вертикальный срез

- Один `ItemInstance` сохраняет идентичность при перемещении.
- Поддержаны отношения `WORLD`, `CONTAINER`, `ATTACHMENT`, `DESTROYED`.
- Предмет в `WORLD` имеет физическое представление `RigidBody3D`.
- Предмет в `CONTAINER` не имеет мировой физики.
- Предмет в `ATTACHMENT` отображается дочерним узлом конструкции без независимой физики.
- Контейнер может быть предметом и владеть собственным `ContainerState`.
- Перемещение заполненного контейнера не переписывает отношения его содержимого.
- Проверяются масса, внешний объём, число слотов, разрешение вложенности и циклы общего графа.
- Операции идемпотентны по `operation_id`.
- Стаки объединяются и разделяются транзакционно.
- Сокеты сборок фильтруют детали по тегам.

## Запуск тестов

```powershell
.\RUN_ITEM_SYSTEM_TESTS.ps1
```

Тесты выполняются headless и завершают процесс ненулевым кодом при любой ошибке.

## Интерактивная лаборатория

```powershell
.\ITEM_SYSTEM_LAB.ps1
```

Управление:

- `1` — подобрать камень;
- `2` — выбросить камень;
- `3` — подобрать заполненный ящик;
- `4` — выбросить заполненный ящик;
- `5` — подобрать лидар;
- `6` — установить лидар на сокет ровера;
- `7` — снять лидар в рюкзак;
- `T` — вывести результат проверки графа в консоль.

## Зафиксированные инварианты

1. У предмета ровно одно отношение размещения.
2. Один `instance_id` не создаётся повторно.
3. Членство в контейнере соответствует `ContainerRelation`.
4. Контейнер не может содержать сам себя или собственного предка.
5. Циклы запрещены одновременно для containment и attachment рёбер.
6. Заполненный контейнер перемещается как один предмет.
7. Масса вложенных предметов учитывается рекурсивно.
8. Внешний контейнер учитывает внешний объём вложенного ящика, а не сумму объёмов его содержимого.
9. Повтор `operation_id` не выполняет операцию второй раз.
10. Представление является производным от доменного состояния и не является источником истины.
