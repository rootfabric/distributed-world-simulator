# Recent Surface Cache v1

## Назначение

Кэш устраняет повторную дорогую генерацию недавно посещённых LOCAL-участков.

Он не является сохранением мира и не заменяет процедурный генератор. После закрытия приложения кэш теряется.

## Что хранится

Для одной terrain streaming cell:

```text
cell_id
generation_state
ArrayMesh LOCAL
массив готовых collision Shape3D
MultiMesh шести слоёв камней
счётчики вершин и треугольников
время помещения в кэш
```

Не хранятся игровые сущности, маяки и terrain delta. Они обслуживаются persistence отдельно.

## Политика памяти

```text
recent_surface_cache_capacity = 8
max_pinned_surface_cells = 8
```

Обычные cells вытесняются по LRU. Cells с постоянными маяками помечаются pinned и получают дополнительное место в кэше.

Таким образом база с маяками не должна быть вытеснена после короткой экспедиции, даже если игрок пересёк больше восьми промежуточных cells.

## Cache hit

```text
приближение к ранее посещённой cell
→ cache lookup
→ отмена устаревшей фоновой job
→ повторное создание лёгких Node-обёрток
→ подключение готовых Mesh/Shape/MultiMesh ресурсов
→ reconcile персонажа
→ swap
```

Дорогие этапы не выполняются:

```text
height sampling
normals
tangents
rock placement
ConcavePolygonShape3D.set_faces
```

## Будущее развитие

Следующий уровень — дисковый cache промежуточных CPU-данных. Он сможет переживать перезапуск приложения, но останется удаляемым и неавторитетным.

## Ранний возврат к базе

Для pinned-cell с маяком используется отдельный порог:

```text
pinned_return_trigger_distance_m = 1800
```

При приближении к базе кэшированная поверхность включается до фактического пересечения центра cell. Проверяется направление движения: при удалении от маяка ранний возврат не срабатывает, чтобы не создать колебание между соседними cells.

События:

```text
terrain_pinned_cache_return_triggered
terrain_surface_cache_hit
```
