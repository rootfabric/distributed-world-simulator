# Чекпоинт разработки: R0 Stabilization

**Дата фиксации:** 26 июля 2026 года  
**Версия:** `v15.5.2-r0`  
**Предыдущая база:** `v15.5.1-fixed`

## Решение по дорожной карте

Проект уже является не отдельной демонстрацией Луны, а каркасом многомирового
симулятора. В нём существуют единое ядро, пять подключаемых миров, единое время,
иерархические системы отсчёта, partition-адресация, persistent lunar world,
процедурная Земля и предметный домен.

Следующий основной вертикальный путь зафиксирован так:

```text
R0: стабилизация текущей базы
→ R1: persistent Item Aggregate и глобальные ID
→ R2: пользовательские контейнеры на playground
→ R3: placement, sockets и строительство
→ R4: минимальная энергетическая база
→ R5: автономный грузовой ровер
```

До завершения R2 не следует начинать полноценную сетевую authority, сложную
деформацию terrain или превращение Земли в отдельный большой gameplay-проект.
Координатный фундамент уже достаточен для будущего разделения процессов, но
сначала нужен сквозной жизненный цикл реальных сущностей.

## Состояние подсистем на чекпоинте

| Подсистема | Состояние | Следующий обязательный шаг |
|---|---|---|
| Multi-world core | рабочий фундамент | удерживать зелёной boot matrix |
| SimulationClock / FrameGraph | рабочий фундамент | использовать во всех новых сущностях |
| PartitionAddress / CubeSphereGrid | готово для локального этапа | не менять без миграции revision |
| Лунный terrain | зрелый прототип | безопасная выгрузка при активной generation |
| Процедурная Земля | визуальный архитектурный прототип | не считать gameplay-поверхностью |
| Item Domain | хороший изолированный домен | persistence, global ID, operation ledger |
| Item presentation | лабораторная интеграция | world-specific physics policy |
| Playground | закрытый тестовый runtime | реальный inventory и ray interaction |
| Роботы | только архитектурное направление | начинать после базы и контейнеров |

## Зафиксированные сильные решения

1. `ItemInstance` отделён от `RigidBody3D` и сценового представления.
2. Один предмет может менять отношения `WORLD`, `CONTAINER`, `ATTACHMENT` без
   смены идентичности.
3. Предметные ограничения и масса проверяются вне визуальной сцены.
4. Координаты поверхности хранятся в body-fixed reference frame.
5. Миры загружаются через один `SimulatorApp` и очищают команды по owner.
6. Earth runtime не создаёт скрытую Луну.

## Известные архитектурные ограничения после R0

Эти пункты не исправляются в R0 и образуют содержание R1/R2:

- последовательные ID предметов не подходят для нескольких процессов и
  постоянных сохранений;
- operation ledger предметов находится только в памяти и не проверяет fingerprint
  повторной команды;
- `capture_world_state()` должен сохранять исходные `frame_id`, `space_id`,
  `universe_id` и `instance_id`;
- сила тяжести предметов пока жёстко связана с Луной;
- физическая масса заполненного контейнера должна учитывать содержимое;
- предметный registry и container registry ещё не сохраняются;
- Earth runtime пока не имеет ходимой collision-поверхности;
- крупные runtime-файлы больше нельзя расширять новой несвязанной логикой;
- наследование `PlanetaryApp extends LunarApp` следует постепенно заменить
  композицией runtime-модулей.

## Что выполнено в R0

### Репозиторий

- добавлен `.gitignore` для `.godot`, `.import` и локальных результатов тестов;
- добавлен `.gitattributes` с единым LF-контрактом для Windows и Linux;
- добавлен `PREPARE_R0_REPOSITORY.ps1`, удаляющий generated Godot state из
  индекса и выполняющий `git add --renormalize`;
- текстовые файлы поставляемого патча нормализованы в LF.

### Версия и документация

- maintenance checkpoint получил версию `v15.5.2-r0`;
- публичный контракт исправлен: в основном SimulatorApp клавиша `F5` переключает
  камеру, а лаборатория открывается командой `world.load item_lab`;
- roadmap и список ближайших итераций ссылаются на этот чекпоинт.

### Regression barrier

`RUN_WORLD_REGRESSION_TESTS.ps1` теперь:

1. запускает headless editor import/parse всего проекта;
2. проверяет, что явный список runner совпадает со всеми `test_*.gd`;
3. отклоняет single-precision сборку отдельным precision contract;
4. запускает hotkey contract;
5. запускает переключение мира при активной terrain generation;
6. выполняет main-scene CLI suite;
7. всегда записывает JSON-отчёт в
   `artifacts/test-results/world-regression-summary.json`.

### Безопасная выгрузка terrain

Перед выгрузкой Lunar/Planetary runtime активный terrain request помечается
устаревшим через `cancel_all("runtime_unload")`. Рабочий поток всё равно корректно
дожидается завершения при освобождении менеджера, но его результат уже не может
перейти в commit после начала смены мира.

## Критерий завершения R0

R0 считается полностью принятым только после выполнения на целевой сборке Godot
4.7.1 `precision=double`:

```powershell
.\PREPARE_R0_REPOSITORY.ps1
.\RUN_WORLD_REGRESSION_TESTS.ps1
```

Ожидается:

- editor import/parse завершается с кодом `0`;
- runner не обнаруживает пропущенных или лишних тестов;
- double-precision contract подтверждает сохранение дробной части на координате `1 000 000 000,125`;
- все headless-тесты проходят;
- `world_switch_during_generation` проходит без зависания, commit старого terrain
  не выполняется после начала unload;
- все пять миров загружаются последовательно в одном процессе;
- JSON-отчёт содержит `passed: true`;
- после commit `git status --short` пуст.

## Следующий этап

Следующий этап — **R1: production-ready Item Aggregate**. Он должен начинаться не
с UI, а с глобальной идентичности, persistence-port, revision fencing,
persistent operation ledger и корректного сохранения `SpatialRef`. После этого
R2 связывает предметы с игроком и playground через ray interaction.
