# Checkpoint R2 stack controls

> UI выбора количества из этого checkpoint заменён в v16.3.0: теперь ПКМ перетаскивает к цели, а количество выбирается после drop.
Версия: `v16.1.0-r2-stack-controls`.

## Цель

Завершить пользовательский контракт стеков для R2 без создания отдельной UI-модели предметов. Все операции остаются командами доменного `ItemTransferService`, защищёнными `expected_revision` и operation ledger.

## Принятое поведение

### Обычный drag-and-drop

ЛКМ переносит весь доступный стак.

- На занятую совместимую ячейку `SLOTS` количество объединяется до `max_stack`.
- Непоместившийся остаток остаётся в исходной ячейке.
- На пустую ячейку `SLOTS` переносится отдельный стак без поиска соседних совместимых стаков.
- В `BULK` совместимые стаки заполняются автоматически по порядку, остаток переносится отдельной записью.

### Частичный перенос

ПКМ открывает popup количества. После подтверждения выбранное количество сохраняется как подготовленный drag payload. Следующее ЛКМ-перетаскивание переносит только это количество.

Подготовленный источник выделяется жёлтой рамкой и показывает `общее количество → количество переноса`.

### Идентичность

Полностью поглощённый source stack удаляется из registry и контейнера. При частичном переносе source aggregate и его UUID сохраняются. Новый UUID создаётся только для реально отделённой части, которая остаётся отдельным aggregate.

### Контейнеры

- `player_inventory` и `demo_crate_contents` — `BULK`.
- `player_hotbar` и `battery_rack_slots` — `SLOTS`.
- Предметы, владеющие контейнерами, имеют `max_stack=1` и не разделяются.

## Автоматическая проверка

`tests/items/test_item_stack_transfers.gd` проверяет:

- различие BULK/SLOTS;
- заполнение занятого слота и сохранение остатка;
- отсутствие auto-stack при переносе на пустой фиксированный слот;
- popup выбора количества;
- частичный перенос в пустой слот;
- полное поглощение source aggregate;
- распределение BULK-переноса по нескольким частичным стакам;
- BULK-контейнер без свободного entry, но с достаточной суммарной ёмкостью;
- нестакуемость индивидуально именованных маяков;
- сохранение общего количества и валидность item graph.

## Стабилизация runtime regression

`test_world_switch_during_generation.gd` теперь использует уже активный predictive terrain request, если он появился во время запуска мира. Если фонового запроса нет, тест создаёт собственный. Это устраняет зависимость от скорости worker thread в headless-сборке, сохраняя исходный контракт: переключение мира должно отменить и fenced-изолировать реально активную генерацию.
