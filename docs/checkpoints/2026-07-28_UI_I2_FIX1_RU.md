# Checkpoint UI-I2 fix1 — bounded pool, operation recency и SLOTS statistics

Дата: 28 июля 2026 года
Checkpoint: `v16.3.6-ui-i2-fix1`
Основа: `v16.3.5-ui-i2`

## Исправленные дефекты

### 1. BULK pool ограничен 96 карточками

Порог page-window теперь совпадает с размером окна: любой `BULK` projection с
количеством результатов больше 96 разбивается на страницы. Диапазон 97–120 больше
не создаёт 97–120 UI-узлов.

`InventoryContainerPanel` дополнительно применяет собственный hard guard:

- перед отрисовкой `BULK` pool уменьшается до 96;
- входной набор карточек ограничивается 96 даже при некорректной модели;
- `SLOTS` по-прежнему может показывать все физические ячейки;
- после перехода с крупного `SLOTS` на `BULK` лишние controls удаляются.

Проверенный пример:

```text
100 совпавших BULK-агрегатов
→ страница 1: 96
→ страница 2: 4
→ pool: 96
```

### 2. Сортировка recent использует operation ledger sequence

Локальная `item.revision` не является глобально сопоставимым временем изменения.
Режим переименован в **«Недавние операции»** и использует sequence последней
успешной записи `ItemOperationLedger`, связанной с предметом.

При построении presentation-модели учитываются:

- `aggregate_id` записи;
- source/target/result/new item IDs результата;
- `merged_into_item_id` и `merged_into_item_ids`.

Rejected/retryable записи не повышают activity sequence. Item Graph и ledger не
изменяются — UI только читает snapshot ledger.

### 3. SLOTS statistics отделена от physical layout

Для `SLOTS` теперь существуют разные показатели:

- `physical_cell_count` — количество физических слотов;
- `rendered_cell_count` — число отображаемых ячеек, включая пустые;
- `used_entries` / `unfiltered_count` — занятые слоты;
- `matched_count` / `projected_total_count` — совпавшие занятые слоты.

Пустые слоты остаются видимыми и принимают drop, но не считаются результатами
поиска. Пример:

```text
4 физических слота
1 занятый слот
несовпадающий запрос
→ rendered = 4
→ used = 1
→ matched = 0
→ «Показано 0 из 1 агрегатов»
```

## Regression coverage

`test_inventory_ui_i2_large_storage.gd` расширен с 34 до 49 assertions и теперь
проверяет:

- точный диапазон 97–120 на примере 100 результатов;
- страницы 96 + 4 и неизменный pool 96;
- operation sequence против локальных revisions 10 и 1;
- 4 physical SLOTS / 1 used / 0 matched;
- корректную итоговую строку поиска;
- сохранение валидности Item Graph.

Низкоуровневые transfer, persistence и container schemas не изменялись.
