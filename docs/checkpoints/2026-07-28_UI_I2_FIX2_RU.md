# UI-I2 fix2 — invalidation кеша недавних операций

Дата: 28 июля 2026 года
Checkpoint: `v16.3.7-ui-i2-fix2`
Родитель: `v16.3.6-ui-i2-fix1`

## Причина

`InventoryViewModel` кешировал отображаемую sequence предметов только по
`ItemOperationLedger.next_sequence`. Persistence может заменить все записи ledger
другим валидным набором с тем же `next_sequence`. В этом случае прежний кеш
оставался активным до следующей операции.

## Решение

В `ItemOperationLedger` добавлена неперсистентная `content_generation`. Она
увеличивается после каждой успешной замены содержимого:

- `remember_terminal()`;
- `clear()`;
- `load_dict()`;
- `replace_from()`, используемого transactional Item Graph persistence.

`to_dict()` и схема `planet_simulator.item_operation_ledger.v1` не содержат
`content_generation`; формат сохранений не изменён.

ViewModel инвалидирует activity cache по тройке:

```text
ledger instance ID
+ content_generation
+ next_sequence
```

Это покрывает как замену записей внутри существующего ledger, так и замену самого
объекта ledger.

## Регрессии

Добавлен сценарий:

```text
исходный ledger: second имеет sequence 2
replacement ledger: first имеет sequence 2
next_sequence у обоих равен 3
```

После `load_dict()` сортировка сразу ставит `first` выше, не ожидая новой операции.

Также проверено:

- generation растёт после terminal write, clear и успешного load;
- не растёт после отклонённого load;
- generation отсутствует в persisted snapshot;
- ItemGraphPersistence использует `replace_from()` и инвалидирует потребителей;
- старые item/UI сценарии не изменились.
