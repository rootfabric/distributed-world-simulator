# Профиль инвентаря 7 Days: реальные слоты и курсорный перенос

Базовый commit: `b34b4f3`.

Ветка: `feature/h0-inventory-menu-debug`.

## Цель

Профиль `seven_days_like` доведён от простой таблицы жестов до отдельного режима
интерфейса и взаимодействия, похожего по принципам на инвентарь 7 Days to Die:

- ЛКМ по предмету берёт весь стак на курсор;
- повторный ЛКМ по слоту кладёт весь переносимый стак;
- ПКМ по предмету берёт округлённую вверх половину стака;
- ПКМ при занятом курсоре кладёт по одной единице;
- ЛКМ по занятому несовместимому слоту меняет предметы местами;
- Shift+ЛКМ выполняет быстрый перенос между рюкзаком и реально открытым контейнером;
- `Esc`, закрытие меню или смена профиля возвращают предмет и разворачивают цепочку
  совершённых обменов.

## Доменная модель слотов

Визуальной проекции BULK-контейнера оказалось недостаточно: два одинаковых стака в
разных клетках немедленно объединялись бы низкоуровневым сервисом. Поэтому добавлен
`InventorySlotModeAdapter`.

При первом включении профиля 7 Days:

1. рюкзак игрока переводится из `BULK` в `SLOTS`;
2. каждому существующему предмету назначается точный `slot_index`;
3. при взаимодействии с внешним контейнером через `E` тот же переход выполняется
   только для реально открытого контейнера;
4. миграция валидирует весь Item Graph, сохраняется и откатывается целиком при
   ошибке.

Переход односторонний: после назначения точных слотов контейнер остаётся `SLOTS` и
при переключении на другие профили. Это сохраняет положение предметов и не создаёт
две конкурирующие модели хранения.

## Промежуточный контроллер курсора

Добавлен `InventoryCursorController`. Он использует временный доменный контейнер из
одного слота с владельцем `UI_TRANSIENT`:

```text
реальный слот → временный контейнер курсора → целевой слот
```

Пока предмет находится на курсоре, persistence временно пропускается. После
успешного размещения или отмены временный контейнер удаляется, Item Graph
валидируется и сохраняется. Это позволяет:

- видеть реальное количество на курсоре;
- класть одну единицу без потери остатка;
- атомарно менять несовместимые предметы местами;
- безопасно отменять несколько последовательных обменов.

## Атомарный обмен

В `ItemTransferService` добавлена операция `SWAP_ITEMS`:

- проверяет revisions обоих предметов;
- проверяет правила слотов, массу и объём конечного состояния;
- обновляет обе relation и оба контейнера одной транзакцией;
- откатывает memberships, relations и revisions при любом отказе;
- поддерживает operation-ledger replay без повторной мутации.

Частичный перенос на несовместимый предмет не превращается в неявный обмен:
возвращается `SWAP_REQUIRES_FULL_STACK`. ПКМ сохраняет семантику «положить одну».

## Визуальный режим

Для `ui_style = SEVEN_DAYS` применяются:

- два слотовых поля: внешний контейнер слева, рюкзак справа;
- десять колонок;
- квадратные клетки 56×56;
- чёрные заголовки с жёлтой границей;
- тёмные полупрозрачные панели;
- количество в правом нижнем углу;
- жёлтая рамка выбранной клетки;
- скрытые универсальные поиск, фильтр, сортировка и inspector;
- отдельная иконка переносимого предмета рядом с курсором.

Persistent hotbar остаётся компактным и не растягивается стилем полноэкранного
инвентаря.

## Защита импорта

Во входной ветке находилась полная копия предыдущего патча внутри
`artifacts/archive-staging`. Godot импортировал её как вторую копию проекта и
получал дубли `class_name` и UID. Добавлен `artifacts/archive-staging/.gdignore`;
сами пользовательские артефакты не удаляются.

## Тесты

Добавлен `tests/ui/test_inventory_seven_days_interface.gd`, проверяющий:

- отдельный skin и раскладку панелей;
- миграцию рюкзака и открытого контейнера в реальные `SLOTS`;
- наличие всех пустых кликабельных слотов;
- ЛКМ взять/положить весь стак;
- ПКМ взять половину и выкладывать по одной;
- обмен несовместимых предметов;
- разворот цепочки обменов при отмене;
- Shift+ЛКМ в обе стороны;
- сохранение точных slot assignments после перезапуска;
- валидность Item Graph и отсутствие оставшегося transient cursor.

`test_item_stack_transfers.gd` дополнен негативной проверкой capacity rollback,
revision conflict и idempotent replay операции обмена.
