# Контракт WORLD_RUNTIME_V1

## Цель

Контракт определяет минимальное взаимодействие между общим ядром симулятора и
подключаемым миром. Он не требует наследования от общего базового класса:
совместимость проверяется по методам, что позволяет подключать как скриптовые
runtime, так и готовые сцены.

## Обязательные методы

### `configure_runtime(context: Dictionary) -> void`

Вызывается до добавления runtime в дерево сцены.

Поля контекста:

| Поле | Тип | Назначение |
|---|---|---|
| `simulator_app` | `Node` | общий координатор |
| `command_registry` | `RefCounted` | единый реестр команд |
| `test_registry` | `RefCounted` | реестр runtime-тестов |
| `command_owner_id` | `String` | владелец команд текущего мира |
| `test_owner_id` | `String` | владелец тестов текущего мира |
| `world_id` | `String` | стабильный ID записи каталога |
| `world_definition` | `Dictionary` | полное описание мира |
| `options` | `Dictionary` | параметры конкретной конфигурации |
| `simulation_clock` | `RefCounted` | единые абсолютные часы симуляции |
| `universe_id` | `String` | namespace постоянной Вселенной |
| `instance_id` | `String` | ID persistent/scenario instance |
| `local_authority_id` | `String` | текущий локальный authority owner |

### `register_runtime_commands(registry, owner_id: String) -> void`

Регистрирует команды текущего мира. Все команды обязаны использовать переданный
`owner_id`, чтобы ядро могло атомарно удалить их при смене мира.
Ошибка регистрации хотя бы одной команды или alias считается ошибкой загрузки всего runtime.

### `register_runtime_tests(registry, owner_id: String) -> void`

Runtime обязан зарегистрировать минимум один smoke-тест. Ошибка или коллизия ID
отменяет загрузку candidate runtime.

Регистрирует минимум один безопасный smoke-тест. Тест не должен требовать
ручного ввода и не должен оставлять мир в повреждённом состоянии.

### `create_runtime_snapshot() -> Dictionary`

Возвращает сериализуемое диагностическое состояние. Минимальные поля:

```text
schema
world_id
```

Дополнительные данные определяются миром.

### `prepare_for_unload() -> void`

Сохраняет обязательное состояние, останавливает фоновые операции, освобождает
захват мыши и отключает внешние подписки. Метод должен быть идемпотентным.

## Рекомендуемые методы

### `execute_runtime_command(command_line: String) -> Dictionary`

Единая точка для HUD и совместимых горячих клавиш. UI не должен напрямую
вызывать внутренние методы мира, когда существует зарегистрированная команда.

### `get_runtime_display_name() -> String`

Человекочитаемое название для диагностики.

## Инварианты

1. Runtime не меняет `main.tscn` и не вызывает `change_scene_to_file` при работе
   под `SimulatorApp`.
2. Runtime не хранит постоянные ссылки на предыдущий или следующий мир.
3. Команды и тесты регистрируются только под переданным owner ID.
4. Общий ввод персонажа реализуется контроллерами, а не картой.
5. Специализированный HUD не дублирует навигацию по мирам.
6. Действия, применимые к нескольким мирам (`world.*`, `input.*`, `display.*`),
   принадлежат ядру и не регистрируются runtime повторно.
7. После `prepare_for_unload` runtime может быть безопасно удалён в том же кадре.
8. Smoke-тест не зависит от порядка загрузки миров.
9. Runtime не создаёт независимые часы, если получил `simulation_clock` из ядра.
10. `world_id` является runtime profile, а не server partition или reference frame.
11. Координаты persistent-объекта передаются как `SpatialRef`, а не через Node3D transform.

## Ошибки загрузки

Ядро возвращает структурированный результат:

```text
success=false
error_code=UNKNOWN_WORLD | RUNTIME_INSTANTIATION_FAILED | INVALID_RUNTIME_CONTRACT | RUNTIME_REGISTRATION_FAILED
output=<человекочитаемое сообщение>
```

Ошибка одного мира не должна уничтожать каталог, консоль или возможность
загрузить другой мир.

## Версионирование

Текущая версия: `WORLD_RUNTIME_V1`.

Несовместимое изменение требует нового контракта и адаптера. Добавление
необязательного метода не меняет major-версию.
