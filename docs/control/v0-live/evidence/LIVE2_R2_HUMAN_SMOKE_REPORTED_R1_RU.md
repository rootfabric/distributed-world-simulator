## Решение

Ручная сессия R2 завершена как диагностический gate с PARTIAL_PLAYABLE. Полная приёмка LIVE.2 и merge #703 этим не разрешаются.

R3 — ограниченный quality/usability repair:
1. Единый согласованный путь изменения видимости инвентаря и владения вводом. Esc/Tab/кнопка/повторный attach не должны оставлять скрытую блокировку.
2. Разобрать фактический путь remote/local presentation; не менять коэффициенты сглаживания без причины. Измерять задержки и корректировки отдельно.
3. Проверить INPUT_QUEUE_FULL на уровне, где очередь возникает. Не выбрасывать canonical item/construction commands и не менять семантику edge-input ради latest-wins.
4. Добавить ограниченную по объёму диагностику отказов: тип, игрок, operation id, причина; без секретов и полных payload.

Сохранить EG4 physical mapping и R2 transport-rotation implementation. Нужны новые тесты R3, точный Windows gate и повторная короткая ручная проверка. Старые PASS относятся только к указанному R2 subject. Новую возможность строительства, новый owner, launcher или новую экономику в R3 не добавлять.
