### R4. Аудит нового механизма отбора (глобальное усечение + копростой шаг 7 mod 25) — РЕЗУЛЬТАТ: ОК

- (a) Детерминизм: ранговый порядок фиксирован — потомки сортируются по parent_fitness (desc) с tie-break по bundle_checksum (asc): `evo7_water_feedback_bridge_v1.gd::313-316`; входные массивы каноничны (популяция сортируется по identity каждый generation `::326-327`, scored строится в этом порядке `::255-280`). Шаг фиксирован: `(rank * 7) % POPULATION_SIZE` `::318`.
- (b) «Одно растение на позицию»: rank ∈ [0, mini(100, 25)) = 0..24; отображение rank → (rank·7) mod 25 инъективно, т.к. gcd(7,25)=1 ⇒ биекция на 25 позициях: дублей позиций и пустых позиций нет.
- (c) Управляемость фитнесом: ранг наследуется от fitness-desc сортировки (`net_resource_proxy`) с checksum tie-break: родители `::290-294`, потомки (по parent_fitness) `::313-316`.
- (d) Пути к дубликату/дырке нет при candidates ≥ 25; здесь candidates = 25·4 = 100 всегда (размер популяции инвариантен: `next_population` получает ровно mini(100,25)=25 записей `::317-325`). Деградация возможна лишь при population < 25 — в этом мосте недостижимо (note N1).
- (e) Инвариант «identity — канонический ключ» не ослаблен: identity жёстко привязан к позиции (p00..p24, `::192-203`), шаг перераспределяет лишь то, какой бандл занимает identity; агрегаторы поля и хэши ключуются/сортируются по identity; уникальность identity в поле enforce'ится fail-closed (`soil_water_field_v1.gd::135-136`). Ни один компонент не предполагает непрерывности «identity ↔ геном». Нюанс про полные совпадения (fitness, checksum) — note N2.
