## 6. Следующая узкая правка (по стадийным измерениям)

1. **Главный кандидат — `send_and_seam_ms` на сервере** (p50 ~21 мс, p99 34–42 мс; ~85 % стадии снапшота): вынести seam-append/отправку из горячего пути кадра (батчирование/отложенная отправка вне snapshot-стадии) — это прямо бьёт по серверному frame p99 и хвостам loop.
2. **Серверные хвосты `message_ms` p99 ~118–120 мс** совпадают с хвостами frame — проверить, не является ли источник синхронный durable command checkpoint; по контракту slice это **вне скоупа** (checkpoint/ACK не менялся), фиксируется как следующий отдельный slice, ему же принадлежит `persistence_ms` p99 63–66 мс.
3. Клиентский frame p99 ~32.5 мс при дешёвом снапшот-пути (~4 мс) — следующий шаг: профилирование рендера/кадрового цикла клиента (вне сетевого hot-path).
