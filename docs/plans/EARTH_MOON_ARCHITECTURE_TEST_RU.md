# План проверки Земли и Луны

## Цель

Проверить, что существующая лунная архитектура допускает добавление полноценного второго небесного тела, независимого procedural rule pipeline и object placement без изменения рабочих модулей Луны.

## Запуск

Открыть проект double-precision сборкой Godot 4.7.1 и запустить `main.tscn`.

На старте активна Луна с исходной логикой v15.2. Нажать `P` для перехода на Землю.

## Управление Землёй

```text
P          Земля / Луна
1          лес
2          травяная равнина
3          каменная пустыня
4          тундра
5          снежные горы
F4         final / biome / elevation / ecology density
Y          перечитать JSON-конвейер правил
WASD       движение
Q / E      вниз / вверх
Shift      ускорение
колесо     изменить базовую скорость
H          выровнять горизонт
```

## Автоматическая проверка

```powershell
.\RUN_EARTH_ARCHITECTURE_TEST.ps1
```

Тест проверяет:

- порядок и целостность rule pipeline;
- наличие всех обязательных выходных полей;
- автоматическое обнаружение двух writers одного поля;
- наличие ocean, desert, tundra, forest, grassland и alpine snow;
- наличие river/lake samples;
- запрет растительности на воде, в пустыне, тундре и снегу;
- реальные радиусы Земли и Луны;
- расстояние 384 400 000 м между центрами.

## Ручная проверка визуальных правил

### Лес

Нажать `1`.

Ожидается:

- несколько геометрических типов деревьев;
- вариативность высоты, ширины и поворота;
- неравномерная плотность;
- трава между деревьями;
- отсутствие деревьев в водных углублениях, на снегу и резких склонах.

### Равнины

Нажать `2`.

Ожидается:

- зелёная procedural surface;
- несколько типов травы;
- участки разной плотности;
- небольшое число деревьев только там, где разрешено biome density.

### Пустыня

Нажать `3`.

Ожидается:

- коричнево-каменная поверхность;
- несколько вариантов камней;
- отсутствие травы и деревьев.

### Тундра

Нажать `4`.

Ожидается:

- положение ближе к полярным поясам;
- снежно-каменная поверхность;
- отсутствие деревьев и травы.

### Снежные горы

Нажать `5`.

Ожидается:

- выраженный горный relief;
- snow mask на высоте;
- камни;
- отсутствие деревьев выше snow cutoff и на крутых склонах.

### Вода

В debug biome вода должна иметь отдельный цвет. В final режиме:

- океан формирует низкую часть планеты;
- реки выражены узкими прорезанными руслами;
- озёра выражены локальными чашами;
- физическая жидкость отсутствует намеренно.

## Проверка LOD

1. На высоте менее 3,5 км должны быть local terrain, объёмные деревья, billboard, трава и камни.
2. Подняться выше 3,5 км: объёмные деревья и трава исчезают, billboard остаются.
3. Подняться выше 30 км: вся растительность и камни исчезают.
4. Подняться выше 180 км: остаётся только global sphere.
5. Сравнить очертания материков, снега и воды между local и global — крупная форма и цвет должны совпадать.

## Нагрузочная проверка

Для каждого режима записать из overlay и profiler:

- время первого перехода на Землю;
- `last_batch_elapsed_ms` global mesh;
- `last_batch_elapsed_ms` local mesh;
- время placement;
- число near trees;
- число billboard trees;
- число grass instances;
- число rocks;
- FPS и frame time.

Повторить после изменения лимитов в `earth_vegetation.json`:

```text
x1 — базовый профиль
x2 — удвоенное число объектов
x4 — стресс-профиль
```

Ожидаемая зависимость placement близка к линейной от количества кандидатов. Draw calls должны расти по числу типов, а не по числу объектов благодаря MultiMesh.

## Проверка роста числа правил

Создать копии диагностического правила с уникальными output fields и добавить их в `earth_rules.json`.

Профили:

```text
5 правил   — baseline
10 правил  — x2 pipeline
25 правил  — x5 pipeline
50 правил  — stress
```

Сравнить время global/local batch. До появления field-tile cache ожидается примерно линейный рост `V × R`. Ошибки порядка или повторная запись поля должны блокировать setup.

## Критерии успешности

- Луна запускается и работает как v15.2.
- Переключение `P` не сбрасывает сохранённые сущности Луны.
- Земля создаётся только при первом входе, не увеличивая стартовое время Луны.
- Все requested biomes визуально различимы.
- Растительность соблюдает water/snow/slope/rock filters.
- LOD удаляет дорогие слои в правильной последовательности.
- При `Y` rule pipeline перечитывается без перезапуска приложения.
- Конфликт writers обнаруживается тестом.
- Реальные радиусы и дистанция отражены в runtime snapshot.

## Ограничения текущего теста

- collision Земли отключена: управление — свободная камера;
- не используется реальная географическая карта Земли;
- вода не имеет shader, поверхности и физики;
- гидрология является procedural mask, а не flow simulation;
- local patch синхронный и предназначен для архитектурного/нагрузочного теста;
- для production потребуется asynchronous tile generation и cache, аналогичный lunar terrain streaming.
