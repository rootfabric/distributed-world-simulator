# ECO EVO3 — Поправки дорожной карты ECO-R78

Статус: `PROPOSED_RESEARCH_POLICY_AMENDMENT / WAITING_INDEPENDENT_REVIEW`.
Ревизия живого трекера: `ECO-R78-2026-08-22`.
Базовый HEAD ветки: `5fc9895`.

## 0. Граница действия поправок

Эти поправки изменяют **только живой policy-слой** исследования ECO EVO3:

```text
изменяется   : config/ecology/eco-evolutionary-ecology-roadmap.v1.json (ECO-R76 → ECO-R78)
не изменяется: config/ecology/eco-evo3-roadmap.v1.json                  (заморожен на E3.0, hash в accepted evidence)
не изменяется: config/ecology/eco-evo3-planetary-ecology-compiler.v1.json (заморожен, hash в accepted evidence)
не изменяется: docs/plans/ECO_EVO3_PLANETARY_ECOLOGY_COMPILER_ROADMAP_RU.md (заморожен с E3.0, git blob bb701b06… в e3_0 evidence)
```

Замороженные на E3.0 артефакты не редактируются: их хеши закреплены в принятой evidence. Любое их изменение требует формальной ревалидации роадмапа (новая ревизия R2 с собственным closure). Поправки ниже реализуемы без этого.

Поправки **не являются acceptance-решением** и не создают production/XFER1-полномочий. До fresh independent Reviewer они имеют статус предложений, зафиксированных в git как branch facts.

## A1. Каталожное измерение генерализации в E3.FINAL

**Мотив.** Вся принятая цепочка E3.1–E3.7 прибита к одному persisted-каталогу (`5fcd8b90…`, ровно 2 вида — E3.7 ассертит и хеш, и точное число записей). E3.8 варьирует планеты при фиксированном каталоге. Ни один этап не доказывает переносимость цепочки на другой/больший каталог без retuning, хотя портативность каталога — исходный смысл EVO2.

**Правило (добавляется к гейту E3.FINAL).** Precommit-пакет E3.FINAL обязан включать предобъявленные варианты persisted SpeciesCatalog:

- расширенный каталог (порядка 10+ видов);
- каталог с вырожденными/граничными распределениями трейтов;
- моно-видовый каталог.

Каждый вариант компилируется точной принятой цепочкой без retuning. Результаты (включая no-colonization) сохраняются как evidence.

## A2. Sealed predictions для unseen-планетов E3.FINAL

**Мотив.** Культура предобъявления уже доказала себя в E3.8 (семейства планет объявлены до reveal). Для E3.FINAL это последний барьер против интерпретации результата задним числом.

**Правило.** Для каждого precommitted unseen-планета до первой компиляции коммитится запечатанный конверт ожидаемого класса исхода: `colonization / no-colonization / reversal`. Вскрытие — только после заморозки скомпилированной программы. Расхождение предсказания и результата не «проваливает» этап, а сохраняется как честная evidence (falsification evidence).

## A3. Исполнительный конверт (execution envelope) E3.FINAL

**Мотив.** Принятые фикстуры крошечны (1 регион, 11 spatial keys, 2 вида). Детерминизм доказан, практическая масштабируемость не измерялась.

**Правило.** Closure E3.FINAL записывает wall-time, пиковую память и размер артефакта на каждый скомпилированный планет и сверяет их с предобъявленным scale-ceiling. Детерминизм без измеримой исполнимости не считается доказанной готовностью.

## A4. Регрессионное замыкание всех принятых этапов

**Мотив.** Каждый этап валидирован на своём exact HEAD; политика `post_freeze_executable_drift_requires_reverification` декларирована, но механически не проверяется на каждом tip.

**Правило.** Введён агрегирующий раннер `RUN_ECO_EVO3_REGRESSION_CLOSURE.py`: в свежих процессах запускает все 8 принятых stage-раннеров (E3.0-архитектура, E3.1…E3.7) read-only и требует `PASS` по каждому. Требование: любое изменение, затрагивающее принятые compiler-поверхности EVO3, сопровождается полным регрессионным замыканием до review.

**Триггер.** Workflow `.github/workflows/e3-regression-closure.yml` добавлен в режиме `workflow_dispatch` (инертный до включения). Автоматические триггеры (`pull_request` с paths-фильтром по принятым поверхностям) включаются отдельным решением Director после первого успешного ручного прогона в CI.

**Требование окружения.** Полное замыкание требует `jsonschema==4.26.0` (тот же пин, что в stage-closure CI; раннер E3.5 ассертит версию). Без него агрегат честно даёт `7/8` с единственным FAIL `jsonschema_version_mismatch` на E3.5 — это ожидаемое поведение строгого режима.

**Верификация на базовом HEAD `0abae912` (2026-08-22):** `RUN_ECO_EVO3_REGRESSION_CLOSURE.py` = 7/8 PASS локально (E3.5 — только version-pin окружения, сеть до PyPI в среде верификации недоступна); линт A5 = 9/9 PASS; JSON трекера валиден. Попутно агрегат выявил и локализовал реальный дефект загрузки в `RUN_ECO_EVO3_ARCHITECTURE_TESTS.py` (экранирование namespace-пакета `tests` установленным в site-packages пакетом; исправлено загрузкой по пути файла — тем же паттерном, что в остальных семи раннерах; печатные идентификаторы и хеши не изменялись).

## A5. Привязка evidence к финальному closure-прогону

**Мотив.** Review E3.8 зафиксировал INFO-1: receipts ссылались на closure run #1 при финальном run #2. Не stale-claim, но источник путаницы для независимого Reviewer.

**Правило.** Evidence maps, receipts и acceptance-чекпойнты обязаны ссылаться на финальный closure run id; вытесненный run id может сохраняться как история, но не может подаваться как финальный. Введён машинный линт `scripts/control/lint_eco_evo3_evidence_sync.py`, сверяющий `*_closure_run_id` / `*_project_control_run_id` живого трекера с текстами acceptance-чекпойнтов.

## A6. Условный follow-up E3.6-R (мульти-снапшотная сезонность)

**Мотив.** E3.6/E3.7 сознательно fail-closed (`UNRESOLVED_SINGLE_SNAPSHOT`), но критерий «достаточного accepted owner temporal evidence», разблокирующего не-вырожденную сезонность, нигде не формализован.

**Правило.** В живой трекер внесён условный пункт `E3.6-R Multi-Snapshot Temporal Envelopes` со статусом `CONDITIONAL_BLOCKED_WAIT_OWNER_TEMPORAL_EVIDENCE`. Разблокировка — только отдельным owner-dispatch, который обязан объявить критерии достаточности evidence. Инвариант: без separate authorization сезонность остаётся fail-closed, ECO не получает ownership TF/ENV.

## A7. XFER1 readiness pre-design

**Мотив.** XFER1 заблокирован внешними каноническими контрактами `G/ENV/MAT/WQ/SD/TF`. Время ожидания можно конвертировать в подготовку без нарушения границы.

**Правило.** Добавлен research-only документ `docs/plans/ECO_XFER1_READINESS_PREDESIGN_RU.md`: какие вопросы каждый канонический контракт должен закрыть, чтобы ECO-binding стал возможен. Документ не авторизует XFER1, не создаёт production-полномочий и не подменяет owner-контракты.

## A8. Синхронизация статусных баннеров prose-документов

**Мотив.** Живой трекер говорил «E3.8 authorized», а исторические prose-документы — «E3.1 NEXT» и «E3.4 CURRENT»: три разных ответа на вопрос «где мы».

**Правило.** Исторические prose-маршруты обязаны нести явный баннер «статус на дату N» с указателем на машинный трекер как единственный живой источник истины; баннеры обновляются тем же control-коммитом, который поднимает ревизию трекера. Исторические разделы при этом не переписываются.

## Порядок вступления в силу

```text

2. Локальная верификация: регрессионное замыкание 8/8, линт PASS, JSON валиден.
3. Fresh independent Reviewer по этому evidence-only коммиту.
4. После Reviewer PASS: включение pull_request-триггера регрессии и привязка линта к гейтам — отдельным control-коммитом.
5. Пункт A1 (каталожные варианты) становится обязывающим для precommit-пакета E3.FINAL.
```

До шага 3 поправки — предложения; существующие принятые гейты E3.1–E3.7 и правила E3.8 не изменяются.
