# ECO EVO4 — Морфология и визуализация видов: Pre-Design

Статус: `RESEARCH_ONLY / NON_AUTHORITATIVE_PREDESIGN`. Документ — материал для решения Director о запуске нового лейна; он **не** авторизует работы, не изменяет роадмап и не касается принятых поверхностей E3.x. Базовое состояние ветки: `a65ce972` (E3.FINAL REVIEW_PASS_PENDING_DIRECTOR_ACCEPTANCE).

## 0. Аудит связи с принятым треком ECO.PH (уточнение после аудита документов)

Аудит показал: значительная часть настоящего предизайна **уже принята** в треке `ECO.PH` (Plant Development & Phenotype, `PH0..PH5-S4 ACCEPTED`, `ECO.PH RESEARCH COMPLETE`):

| Идея предизайна | Уже принято в ECO.PH |
|---|---|
| Двухслойная архитектура «детерминированный blueprint + презентационный рендер» | Инварианты PH: `GrowthGraph` — derived representation, population is truth; `PH5` rendering architecture (`PlantRenderDescription → RendererProfile → Multi-Scale`) |
| Морфогенетические гены | `PH0 Development Trait Contract` — разделение genome на ecological/metabolic и **developmental traits** (готовый список: internode_length, apical_dominance, branch_*, leaf_*, root_*, тропизмы) |
| Гибрид «грамматика + органы + материалы» | Принятый пайплайн: stochastic parametric grammar (P0) → tube/ArrayMesh ветви + instanced foliage (PH5-S2) → archetype-листва; renderer profiles `DEBUG_SKELETON..IMPOSTOR_BILLBOARD`, тиры `TIER_0..TIER_4` |
| Пластичность по условиям | `PH2 Environment-Coupled Development` ACCEPTED |
| Seeded индивидуальный джиттер | `IndividualSeed = hash(parent_lineage, reproduction_event, seed_index, genome_revision)` — принятый контракт PH0/PH4 |
| Формула «Phenotype = Genome × Environment × Age × History × Seed» | Принята дословно в PH |
| Запрет канонических классов TREE/BUSH/GRASS, смена asset pack не меняет ecological hash | Принятые инварианты + `EXP-V9 Phenotype Projection PASS` |
| Materialization при визите игрока | `PopulationPatch + genome + individual_seed + local environment → derived individual phenotype`; promoted individuals — `PH6` (после canonical production foundations) |

**Следствие: новизна сужается до «моста» EVO3↔PH.** PH-машинария построена на локальном контуре P1-эры (EnvironmentSample/PopulationPatch) и потребляет developmental traits, которых нет в persisted SpeciesCatalog эпохи EVO2/EVO3 (геном v1 — только metabolic-поля). Планетарная цепь EVO3 (opportunity fields, патчи, программы колонизации, unseen worlds) никогда не соединялась с PH. Предмет настоящего предизайна после аудита — **bridge-лейн E4.B**, а не новый визуальный компилятор. Разделы §3–§5 ниже сохранены как сверка дизайна с принятым; эскиз лейна (§9) переписан на bridge-шаги.

## 1. Постановка задачи

Механизм эволюции должен доводить результат до наблюдаемого вида: новый вид растения, возникший эволюционно под конкретными условиями участка симулятора, должен быть отображён визуально в симуляторе (Godot), причём:

- облик связан с признаками генома и условиями места роста;
- особи одного вида различаются между собой (индивидуальное разнообразие);
- один и тот же вид в разных условиях выглядит правдоподобно по-разному (пластичность);
- при посещении игроком другой точки планеты там появляются «заготовленные» виды, выросшие согласно пройденной эволюции.

В перспективе тот же принцип обобщается на крупных существ (горизонт E5).

## 2. Что уже есть в цепи (фундамент)

- **Геном v1** (`distributed_world_simulator.ecology.plant_genome.v1`): `height_m`, `growth_rate`, `root_depth_m`, `water_preference`, `water_tolerance_width`, `shade_tolerance`, `seed_count`, `seed_dispersal_distance_m`, `lifespan_years`; рекрутмент: `dormancy_fraction`, `seed_bank_half_life_years`. Половина полей уже участвует в отборе (establishment/dispersal в E3.4 считаются из них) — визуал, привязанный к этим полям, автоматически «эволюционно честный».
- **Условия места**: патчи E3.3 несут вектор возможностей (вода/свет/питание/persistence/limiting, ppm-шкала); температура и disturbance — в снапшоте E3.1; регионы и рёбра связности задают пространственную структуру.
- **Когорты**: программы колонизации E3.4 фиксируют факт и контекст установления вида на патче.
- **Дисциплина харнесса**: целочисленная ppm-арифметика, канонический JSON, self-hash артефактов, fresh-process replay, запреты продвижения полномочий, `canonical_species_declared=false`.

## 3. Целевая архитектура: два слоя

### Слой 1 — морфологический компилятор (в цепи, детерминированный)

```
(геном, вектор условий патча, instance_seed) -> PlantBlueprint
instance_seed = SHA256(genome_hash | stable_spatial_key | cohort_index)
```

PlantBlueprint — новый тип хешированного артефакта (рабочее имя схемы `distributed_world_simulator.ecology.evo4_plant_morphology_blueprint.v1`), эскиз состава:

- скелет: граф сегментов (узлы: позиция/направление/толщина/возраст) либо эквивалентная параметрическая грамматика;
- параметры органов: лист/цветок/плод/кора — выбор и масштабы;
- палитровые якоря: базовые пигменты и модификаторы от условий;
- класс когорты/стадии роста;
- provenance: входные хеши, reused_modules, `input_verification`;
- self-hash по дому (`object_hash`);

Все атрибуты дома: `RESEARCH_DERIVED_NON_AUTHORITATIVE`, запреты продвижений, fresh-process replay, каноническая сериализация через capability-bound serializer.

### Слой 2 — рендерер-интерпретатор в Godot (презентация)

Интерпретирует blueprint в меш/скелет/инстансы (MultiMesh), LOD, анимацию ветра. Презентационная свобода: материалы/частицы/пост-обработка волевольны, пока hash blueprint сохраняется. Рендер никогда не пишет в цепь.

**Инвариант слоя**: blueprint — истина; пиксели — нет (аналог принятого `compiled_suitability_is_population_truth=false`).

## 4. Четыре источника визуального разнообразия

### A. Прямое маппирование существующих признаков (доступно сразу)

| Поле генома | Визуальное выражение |
|---|---|
| height_m | число сегментов ствола, общая высота |
| growth_rate | стадия роста, ювенильная/взрослая интерполяция формы |
| root_depth_m | комель, наплывы у основания |
| water_preference / water_tolerance_width | суккулентность листа, восковой налёт, оттенок зелени |
| shade_tolerance | площадь и тонкость листовой пластины, угол наклона |
| seed_count | плотность соцветий/плодов |
| seed_dispersal_distance_m | разлёт кроны, форма диаспор (крылатки/ягоды) |
| lifespan_years | толщина и трещиноватость коры, ярусность кроны |
| dormancy_fraction | листопадность (активируется после решения сезонности E3.6-R) |

Ограничение: девять измерений дают ограниченное ортогональное пространство — риск однообразия без источников B–D.

### B. Морфогенетические гены (расширение генома v2, additive-схема)

Новый блок генов, каждый — параметр детерминированной грамматики: филлотаксис (угол ветвления, золотой угол ± смещение), длина междоузлия, вероятность ветвления по глубине, апикальное доминирование, форма листа (коэффициенты суперформулы/Фурье), пигментная триада, поверхность (опушение/шипы/воск/толщина кутикулы), число модулей повторения, архитектура корня, кластер цветения.

**Правило эволюционной честности**: каждый новый визуальный ген связывается с существующим функциональным признаком или условием отбора (пигмент ↔ свет/вода, шипы ↔ disturbance, площадь листа ↔ shade_tolerance). Декоративные гены без функциональной связи запрещены схемой.

### C. Фенотипическая пластичность по условиям патча

Компилятор модулирует выражение генов от вектора патча: дефицит питания → тоньше стебель/мельче лист; избыток света → плотнее крона; высокое disturbance → низкая приземистая форма с утолщённым базальным стволом; водный стресс → укрупнение кутикулы, сдвиг оттенка. Даёт внутривидовое разнообразие «тот же вид вырос здесь иначе» без новых видов.

### D. Детерминированный индивидуальный джиттер и когорты

Особи сегодня в цепи отсутствуют (`individual_entity_count=0`); для рендера экземпляр определяется стабильным сидом (см. §3). Джиттер грамматики от сида воспроизводим и не нарушает запрет RNG. Когортность берётся из программ колонизации: старые установления рендерятся более массивными формами, недавние — ювенильными.

## 5. Представление blueprint: гибридная модель (рекомендация)

- **Скелет**: детерминированная L-грамматика/граф сегментов; альтернатива — space colonization по точкам притяжения (чуть тяжелее, тоже детерминируема).
- **Органы**: библиотека авторских мешей (лист/кора/цветок/плод), выбираемых бакетами генов и масштабируемых условиями; инстансинг через MultiMesh.
- **Материалы**: блендинг параметров (цвет = пигментные гены × свет/вода-стресс).
- За горизонтом (E5+): mesh-morphing и нейросетевые представления; существа — тот же blueprint-принцип на скелетных графах (гены пропорций тела, локомоция).

## 6. Сценарий «игрок посетил другую точку планеты»

Цепь уже выдаёт, какие виды установились и где (регионы E3.3/E3.7). Недостающий элемент — **детерминированное правило сэмплирования условий в произвольной точке** (сейчас 12 сэмплов на фикстуру): ближайший патч или билинейная интерполяция по сэмплам, объявленное в контракте. Формула заспавна:

```
blueprints(виды региона) × условия(точка) × seed(точка) -> популяция экземпляров
когортный возраст <- программа колонизации
```

## 7. Гейт-пакет (по образцу принятых практик)

1. **Гейт разнообразия**: фич-вектор blueprint'а; распределение попарных расстояний по N генотипам × условиям; порог покрытия — защита от «всё одинаковое».
2. **Гейт пластичности**: возмущение условий патча при фиксированном геноме; направление изменения формы должно совпасть с предрегистрированным ожиданием (sealed prediction style — прямой аналог матрицы семейств E3.8).
3. **Визуальная регрессия**: структурные ассерты blueprint'а + машинные скриншоты по контракту `docs/MCP_GODOT.md`; пиксели не являются истиной и не хешируются как таковые.
4. **Границы полномочий**: никакого канонического таксона (`canonical_species_declared=false` остаётся); рендер не мутирует blueprint; эстетическая обратная связь («нравится/не нравится») не возвращается в принятые артефакты иначе чем через amendment.

## 8. Быстрый демо-путь (до замораживания каких-либо схем)

Одной итерацией доказать трубу end-to-end: взять существующую запись каталога (`genome/e22-beta`), набросать v0-деривацию blueprint временным скриптом вне принятых поверхностей, отрендерить трубчатый меш дерева в Godot из JSON, снять скриншот по контракту MCP_GODOT. Только после живой демонстрации — решение о schema freeze.

## 9. Эскиз лейна E4 (после аудита: bridge-шаги поверх принятого PH)

Порядок и правила адекватности: каждый шаг несёт собственный closure-гейт; входы только из принятых артефактов; никакой параллельной истины; статусы `PROPOSED_PENDING_AUTHORIZATION`, запуск лейна — отдельный authorization dispatch после acceptance E3.FINAL.

- **E4.B0 — демо-труба моста**: одна запись persisted SpeciesCatalog (`genome/e22-beta`) → детерминированная деривация developmental-параметров v0 → GrowthGraph skeleton (PH1-паттерн) → рендер профилем `BRANCH_TUBES`/`BRANCH_LEAF_INSTANCED`. Гейт: принятые PH1 morph-tests (sweep apical dominance / branch angle / internode → плавные переходы tree↔shrub без классов) + детерминизм graph hash. Research scratch, без schema freeze.
- **E4.B1 — amendment каталога**: additive блок DevelopmentTraits в persisted SpeciesCatalog по контракту PH0. Двухступенчатая честность: **v0 — traits детерминированно деривируются из metabolic-полей** (честность по построению, новой поверхности отбора нет); v1 (отдельное решение) — независимые гены с двусторонней экологической связью, что требует собственной стадии связывания с causal model по механизмам CAL1 и не может делаться мостом (ретюнинг принятого E3.4 запрещён).
- **E4.B2 — bridge-компилятор**: `(catalog entry + EVO3 opportunity vector + IndividualSeed + возраст когорты) → DevelopmentState/GrowthGraph seed params`. IndividualSeed выводится детерминированно из `(genome_hash, stable_spatial_key, establishment_order)` по духу PH0-контракта. Обязателен объявленный bridge-контракт соответствия единиц (ppm-вектора возможностей → ресурсы грамматики). Плюс **демографический синтез**: детерминированное возрастное распределение патча из (порядок установления, disturbance-история, lifespan_years) — без притязаний на population truth.
- **E4.B3 — гейт пластичности на EVO3-условиях**: sealed directions (аналог матрицы семейств E3.8 и PH2 morph tests): сухой/влажный/теневой/нарушенный патч при том же геноме → предрегистрированное направление формы. Сюда же — выражение disturbance в форме (приземистость, детерминированные «шрамы» от сида).
- **E4.B4 — гейты разнообразия и различимости**: (а) фич-вектор blueprint'а (высота, разлёт кроны, глубина ветвления, плотность листвы, тропизм-наклон, гистограмма оттенков) по N генотипам × условиям × сидам — порог покрытия против коллапса; (б) **silhouette fingerprint**: межвидовое расстояние силуэтов > внутривидовой вариации при том же геноме — вид должен быть узнаваем «на глаз».
- **E4.B5 — контракт сэмплирования условий в произвольной точке планеты**: nearest-patch или билинейное по сэмплам E3.1/E3.2, объявленный в контракте (детерминированно).
- **E4.B6 — materialization региона**: спавн экземпляров из принятой программы E3.7/E3.FINAL по регионам с когортными возрастами; рендер принятыми PH5-профилями; фиксированные камеры-риг для сравнимых скриншотов через MCP_GODOT.
- **E4.B7 — scale/perf probe**: материал региона ~1000 экземпляров под политикой тиров PH5-S3 (дальние — TIER_2/3/POPULATION_ONLY); измеренные инстанс-бюджеты как вход для CONV0-A/WQ-WB обсуждений.
- **Горизонт E4.T**: multi-trophic ecosystem and coevolution (исходная declared goal EVO4) — defense/spines-гены становятся трофическими признаками; строится ПОСЛЕ/ПАРАЛЛЕЛЬНО мосту, т.к. без видимой морфологии коэволюцию нельзя наблюдать.

Запрещено: параллельный визуальный компилятор вне PH-наследия; расширение PH5 core (closure boundary: новые идеи идут через CONV0/CAL1-P2/P3-PH6 контексты); планетарная индивидуальная истина (`planet-wide individual GrowthGraph truth` остаётся запрещённой).

### 9.1. Дополнительные идеи (не входят в минимальный путь, кандидатуры для более поздних шагов)

1. **Growth timelapse replay**: детерминированность деривации позволяет проигрывать рост экземпляра от прорастания до текущего состояния — дёшево, сильно для демо и верификации пластичности.
2. **Herbarium atlas**: автогенерируемый «визуальный определитель» программы (contact sheet всех видов с их условиями и хешами) — человекочитаемое приложение к Evidence Map, преемник HTML-отчёта E3.FINAL.
3. **Редкие косметические морфы** (1-из-N, например кристатные формы): только на стороне рендер-профиля из того же сида — ноль влияния на цепь, максимум удивления.
4. **Lineage paleo forms**: каталоги несут `ancestry_path` — визуализация предковых vs производных форм вдоль линии делает эволюцию наблюдаемой (после B2).
5. **Сезонные состояния** (листопад по dormancy_fraction): `BLOCKED_WAIT_E36_R` — fail-closed до решения сезонности, как в трекере.
6. **Asset-pack swap invariance на планетарном уровне**: расширение правила EXP-V9 — замена орган-мешей не меняет ни одного хеша цепи; тестовый гейт для B6.
7. **Существа (E5+)**: тот же принцип на скелетных графах (гены пропорций тела, локомоция) — отдельный предизайн, здесь только якорь.

## 10. Открытые вопросы

1. Правило сэмплирования условий в точке: nearest-patch vs билинейное по сэмплам (детерминированность обязательна в обоих случаях). — решается на E4.B5.
2. Владелец библиотеки орган-мешей: PH5 оставил archetype-наследие; вопрос о расширении библиотеки и формате поставки (Godot scene pack vs glTF) — арт-лейн.
3. Бюджет полигонов/инстансов на чанк: измеряется E4.B7, решение за CONV0-A/WQ-WB; политика LOD уже принята (PH5-S3 тиры).
4. Момент передачи визуала из research-контура в продуктовый (V0 P-лейны): какие полномочия нужны и кто их выдаёт.
5. Ступень B1-v1 (независимые developmental гены с двусторонней связью к causal model): объём, механизмы CAL1, отдельная авторизация — сознательно вынесено за мост.
6. Демографический синтез возрастов (E4.B2): достаточно ли порядка установления + disturbance-истории или нужна явная мини-модель смертности (исследовательский вопрос без truth-притязаний).
7. Нужен ли промежуточный «морфологический» уровень (body-plan) между геномом и грамматикой, или грамматика напрямую параметризуется генами — решится на B0/B2 по факту поведения trait-space.
