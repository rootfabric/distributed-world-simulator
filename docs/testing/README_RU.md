# Развитие системы тестирования PlanetSimulator

Этот раздел фиксирует текущее состояние автоматических тестов, результаты
исследования практик Godot и поэтапный план расширения покрытия.

Документы созданы как **план развития**, без изменения production-кода, сцен,
конфигураций и существующих тестов.

## Документы

1. [Стратегия тестирования](TESTING_STRATEGY_RU.md) — принципы, уровни тестов,
   правила для Godot, физики, input, асинхронных операций и CI.
2. [Аудит текущего покрытия](CURRENT_COVERAGE_AUDIT_RU.md) — что уже проверяется,
   какие зоны покрыты частично и где находятся основные риски.
3. [Дорожная карта покрытия](TEST_COVERAGE_ROADMAP_RU.md) — последовательность
   небольших этапов, приоритеты и критерии готовности.
4. [Правила проектирования тестов](TEST_DESIGN_GUIDE_RU.md) — требования к новым
   тестам, именованию, изоляции состояния, timeout и диагностике.

## Зафиксированное решение

Существующая система тестов остаётся основной:

```text
Godot double-precision editor
→ --headless
→ отдельный SceneTree test script
→ exit code 0/1
→ PowerShell regression runner
```

Никакой полной миграции на сторонний framework не планируется. GUT или GdUnit4
могут быть добавлены позже как дополнительный инструмент для assertions, mocks,
input helpers или JUnit, только если они совместимы с используемой версией Godot
и не дублируют существующий runner.

## Текущий ориентир

Аудит исходного полного архива показал:

- 79 production GDScript-файлов;
- 23 файла `test_*.gd`;
- 25 GDScript-файлов в каталоге `tests`, включая support;
- около 3600 строк тестового кода;
- около 23 981 строки production GDScript.

После применения R0 и R1.1 обязательный regression manifest должен содержать
26 тестов. Перед началом каждого этапа дорожной карты эти числа следует
пересчитать автоматически, поскольку проект активно развивается.

## Главный принцип

Цель — не максимальный процент строк сам по себе. Цель — гарантировать
инварианты симуляции:

- сохранение идентичности и данных;
- отсутствие частично применённых операций;
- корректный lifecycle миров и фоновых задач;
- валидность координат и partition addressing;
- отсутствие дублирования физических представлений;
- безопасный save/load;
- воспроизводимость procedural generation;
- отсутствие orphan nodes, worker threads и утечек runtime-команд.
